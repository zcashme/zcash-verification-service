# zfa-backend

The ZFA (Zcash Factor Authentication) worker — a Rust background process that watches the Zcash mempool for shielded login payments and sends deterministic OTP responses.

## What it does

```
Consumer app server             response ledger       ZFA worker
───────────────────             ───────────────       ──────────
creates app session                                      connects to lightwalletd (zec.rocks)
renders ZIP-321 QR               incoming txid ──→      watches GetMempoolStream
verifies OTP locally             response txid          decrypts and sends OTP response
```

The worker owns one shielded Zcash wallet. It watches the mempool, trial-decrypts incoming payments with its viewing keys, and when it detects an auth payment above the minimum threshold, constructs and broadcasts an OTP response transaction back to the sender's return address. The OTP code is in the transaction memo.

The worker is **not an API server** and does **not own login sessions**. The consumer application creates sessions, renders the ZIP-321 payment request, and verifies the OTP locally using the same HMAC key.

## Quick start

```bash
# Initialize a new wallet (generates mnemonic, age identity, writes zfa.toml)
cargo run -- init

# The init command prints:
#   - The mnemonic (save it)
#   - The OTP HMAC key (hex) — provision your consumer app server with this
#   - The service address (where users send auth payments)

# Run the worker
cargo run
```

To restore from an existing mnemonic:

```bash
ZFA_MNEMONIC="your twenty four word phrase here" cargo run -- init --restore --birthday 1234567
```

## Configuration

### `zfa.toml` — the only config file

```toml
[seed]
birthday = 1234567
mnemonic = """
-----BEGIN AGE ENCRYPTED FILE-----
<age-armored ciphertext of the BIP-39 mnemonic>
-----END AGE ENCRYPTED FILE-----
"""
```

Written by `init`, mode `0600`, never hand-edited. Contains only the encrypted wallet seed and birthday.

### `identity.txt` — age decryption key

Auto-generated by `init`, mode `0600`. The age x25519 private key that decrypts the mnemonic. Separate from `zfa.toml` because it's the key to the lock — if `zfa.toml` leaks, the mnemonic is still safe.

### On-disk layout

```
./zfa-data/
├── zfa.toml           # [seed] table (0600)
├── identity.txt       # age decryption key (0600)
├── data.sqlite        # wallet DB (0600)
├── blocks/            # compact block cache
├── responses.sqlite   # OTP response idempotence ledger
└── .datadir.lock       # single-instance guard
```

### CLI flags

| Flag | Default | Purpose |
|---|---|---|
| `--conf <FILE>` | `./zfa-data/zfa.toml` | Path to config file |
| `--keys-file <FILE>` | same as `--conf` | Escape hatch: `[seed]` from external file (k8s Secret) |
| `--datadir <DIR>` | `./zfa-data` | Data directory |
| `--network <NET>` | `main` | `main`, `test`, or `regtest` |
| `--lwd-url <URL>` | `https://zec.rocks:443` | lightwalletd/Zaino gRPC endpoint |

### Environment variables

| Env var | Required | Purpose |
|---|---|---|
| `ZFA_MNEMONIC` | No | Mnemonic for `init --restore` (non-interactive) |
| `RUST_LOG` | No | Override log level (default: `info`) |
| `ZFA_REGTEST_NU63_HEIGHT` | No | NU6.3 activation height for regtest |
| `ZFA_ALLOW_CORE_DUMPS` | No | Set `1` to disable core-dump suppression (debugging) |

## OTP key derivation

The OTP HMAC key is **not** an env var or config file entry. It's derived from the wallet seed:

```
HMAC-SHA256(seed, "zfa-otp-v1")
```

`init` prints the hex-encoded key once. Provision your consumer app server with it. Both sides derive the same key from the same seed — no shared secret to rotate independently.

The OTP code itself: `HMAC-SHA256(otp_key, session_id + ":" + return_address)[0..4]` — a 4-byte code sent in the response transaction memo.

## Security

- **Seed at rest:** BIP-39 mnemonic is age-encrypted (x25519 identity file model). The decrypted seed lives in `mlock`'d, zeroized memory (`SeedKeeper`).
- **No core dumps:** `RLIMIT_CORE = 0`, `PR_SET_DUMPABLE = 0` (Linux). Escape hatch: `ZFA_ALLOW_CORE_DUMPS=1`.
- **File permissions:** `zfa.toml`, `identity.txt`, and `data.sqlite` are all `0600`. The age identity is permission-checked at load time (SSH-style — refuses group/other-readable).
- **Database binding:** At startup, the worker derives a UFVK from the decrypted seed and compares it to the wallet database's account UFVK. A swapped `data.sqlite` fails closed.
- **Single instance:** An advisory file lock on `./zfa-data/.datadir.lock` prevents two workers from corrupting the same data directory.
- **Idempotence:** The response ledger (`responses.sqlite`) ensures each incoming auth payment gets exactly one OTP response, even across crashes.

## Architecture

```
zfa-backend
├── src/
│   ├── main.rs              # CLI entry point
│   ├── lib.rs               # init_wallet + run (worker lifecycle)
│   ├── config.rs            # zfa.toml parsing, hardcoded defaults, OTP derivation
│   ├── network.rs            # ZNetwork (mainnet/testnet/regtest)
│   ├── lwd.rs                # lightwalletd gRPC client
│   ├── sync.rs               # block sync engine
│   ├── watcher.rs            # mempool watcher
│   ├── otp.rs                # OTP code generation (HMAC-SHA256)
│   ├── memo.rs               # ZIP-302 memo parsing
│   ├── response_ledger.rs    # OTP response idempotence (SQLite)
│   ├── hardening.rs          # mlock, RLIMIT_CORE, PR_SET_DUMPABLE
│   ├── lock.rs               # single-instance datadir lock
│   ├── backoff.rs            # exponential backoff with jitter
│   ├── error.rs              # error types
│   └── wallet/
│       ├── actor.rs          # single-writer actor (sync + mempool + send)
│       ├── keys.rs           # SeedKeeper, OtpSecret, age decryption
│       ├── store.rs          # zfa.toml [seed] table read/write
│       ├── binding.rs        # seed→database UFVK cross-check
│       └── open.rs           # zcash_client_sqlite DB init
```

## Build

```bash
cargo build --release
```

Requires Rust 1.88+. The Orchard proving key is bundled (`zcash_proofs` with `bundled-prover`), so no external parameter files are needed.
